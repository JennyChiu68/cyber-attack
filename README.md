# 网络安全事件追踪

中文响应式网页应用。时间线收录网络安全事件、公开调查报道和重大服务中断，按最新日期排列，支持关键词搜索、事件类型和重点筛选，并可查看影响范围及出处名称。

## 本地运行

在本目录执行 `python3 -m http.server 8765 --bind 127.0.0.1 --directory dist`，浏览器访问 `http://127.0.0.1:8765/`。应用使用原生 HTML、CSS 和 JavaScript，可将 `dist/` 直接发布到静态主机。

## 数据与更新

- `dist/data.js` 保存经人工核验的精选事件。日期采用公开报道、机构通报或主要进展日期，已知的发生或发现日期另列。重点由人工逐条标注。依据当事机构、监管部门或服务商公开披露的影响，满足以下任一条件时，用 `priority: { criterion, reason }` 记录一个适用条件和具体原因。没有机构证据的媒体报道仍可收录在时间线。
  - 交通、政务、医疗、应急、能源设备供应或通用云服务等关键业务中断、明显受限、出现错误警报，或其核心运行系统遭入侵。
  - 已确认或可能影响至少 10 万人、账户或记录，或同一事件已波及多个机构或运营站点。
  - 支付卡、身份证件或医疗等敏感资料遭未授权访问或泄露。
- `sources/source-directory.js` 维护长期查证渠道。新闻和社交媒体账号用于发现线索。记录证据状态时，区分官方公告、机构经媒体发布的回应和记者独立报道。
- `sources/feeds.js` 保留泄露通报、媒体 RSS 和服务状态的公开接口及解析方法，供查证事件时使用。时间线按复核后的 `dist/data.js` 更新。

## 重大事件查漏

1. **每日找新增，回扫近 7 天。** 并行查交易所、政府及行业通报、服务状态页和独立媒体。对重点地区使用当地语言和机构原名搜索。按首次可靠披露或重要更新日期回扫，覆盖延迟披露。
2. **按影响核对，再去重。** 优先核查关键服务受影响、可能影响十万以上或多机构、敏感数据受影响的事件。每起事件保留当事机构及证据状态。同一供应商事件的下游公告归入原事件，分别列明已确认范围、可能范围和统计单位。单独出现的未经核实社交媒体帖文进入待核线索。
3. **每周用独立来源对账近 30 天。** 从独立监管目录、地区媒体和事件档案，按既定条件先整理参照清单，再与时间线逐条匹配；每月另查 CERT-EU 等延迟汇编。记录窗口、样本数、已覆盖数、漏项及原因。覆盖率以匹配的独立参照事件数除以参照清单事件数。同步跟踪首次可靠披露到上线的时差，并按地区及行业复核长期空白。
4. **检查信源本身是否断更。** 记录每个入口的最后成功核对时间、最新公告日期及失败原因。结构化接口失败时查官方网页或其他独立渠道，把抓取失败单列。以上是维护流程，需有人按频率执行并记录，当前时间线按人工复核发布。

2026 年 11 月 26 日定向回查从官方披露补录 7 起事件，其中 6 起符合重点条件，并归并了 KARTE 事件中漏掉的 ZOZO 公告。这次回查用于发现缺口，未建立覆盖率的独立参照样本。

### X 与 Telegram

先看媒体快讯、应急机构和服务状态三类信号。社交帖进入待核时，记录帖文时间、运营者、涉及机构和原始公告或报道。同一机构在 X、Telegram 和官网的重复发布只算一个出处。网络遥测可以确认地区或网络的可用性异常，攻击归因需另核实。只引用社交转述、媒体转载或未经证实说法的事件继续待核，直到取得当事机构披露或独立采访等可核查的证据。

常设账号和公开网页见 `sources/source-directory.js`。2026 年 11 月 26 日核对了 9 个 X 和 6 个 Telegram 入口。X 部分主页无法直接读取，按发布方的官方回链确认账号，并用官网最新记录检查信源是否仍可用。Telegram 使用公开频道预览。每次回查记录最近可见帖子和校验时间，遇到限流或登录限制时使用清单中的官网或状态页。
